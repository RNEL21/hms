# 🏨 HMS — Hotel Management System

Полнофункциональная система управления гостиницей: номерной фонд, гости, бронирования, аналитика. Backend на Node.js/Express/PostgreSQL, frontend — на чистом JavaScript без фреймворков, с собственной дизайн-системой (светлая/тёмная тема).

Разработано как pet-проект для отработки full-stack паттернов: от проектирования схемы БД и REST API до аутентификации и UX-деталей интерфейса.

---

## Возможности

**Управление номерами**
- CRUD номерного фонда с автоподстановкой цены по типу
- Статусная модель: свободен / занят / недоступен (с пометкой причины) + отдельный флаг "требует уборки", не завязанный на основной статус
- Фильтрация, поиск, пагинация с выбором количества элементов на странице

**Гости**
- Хранение персональных и паспортных данных
- Маскированный ввод телефона и паспорта (IMask.js) — исключает некорректный формат на этапе ввода
- Поиск по имени, телефону, email, номеру паспорта

**Бронирования**
- Создание брони с поиском существующего гостя или инлайн-регистрацией нового прямо в форме — без необходимости уходить на отдельный экран
- Быстрое бронирование прямо с главной панели
- Серверная проверка пересечения дат — нельзя забронировать номер на даты, которые уже заняты другой активной бронью
- Транзакционное создание брони с `SELECT ... FOR UPDATE` — защита от гонки при одновременном бронировании одного номера

**Дашборд**
- Статистика занятости и бронирований в реальном времени
- Графики (Chart.js): динамика бронирований, распределение по типам номеров
- Уведомление о гостях с выездом сегодня

**Интерфейс**
- Светлая/тёмная тема с полностью раздельной цветовой палитрой
- Адаптивная вёрстка: desktop / планшет / мобильный (с отдельной мобильной навигацией)
- Кастомная дизайн-система на CSS-переменных — без Bootstrap/Tailwind/Material

## Технические решения, которые стоит отметить

- **Аутентификация**: JWT в httpOnly-cookie (не localStorage — защита от кражи токена через XSS), пароли хешируются `bcrypt`, серверная мидлварь защищает все API-маршруты
- **XSS-защита**: экранирование пользовательских данных перед вставкой в DOM
- **Целостность данных на уровне БД**: внешние ключи с `ON DELETE RESTRICT` — Postgres физически не даст удалить гостя или номер, если на них есть активные бронирования
- **Валидация в два слоя**: клиентская (мгновенный фидбэк) + серверная (не доверяем фронтенду), включая проверку email, обязательных полей, диапазона цен, порядка дат
- **SQL**: только параметризованные запросы (`$1, $2, ...`), исключены SQL-инъекции

## Запуск локально

**Требования:** Node.js 18+, PostgreSQL 14+

```bash
# установка зависимостей
npm install

# создать базу данных
createdb hotel

# применить схему
psql -U <ваш_пользователь> -d hotel -f schema.sql
```

Создать `.env` в корне проекта:
```env
PORT=5000

DB_HOST=localhost
DB_USER=postgres
DB_PASS=<ваш_пароль>
DB_NAME=hotel

JWT_SECRET=<любая длинная случайная строка>
```

Запуск:
```bash
npm run dev    # с автоперезапуском (nodemon)
# или
npm start      # production
```

Приложение поднимется на порту, указанном в `.env`. При первом запуске понадобится зарегистрировать собственный аккаунт через форму регистрации на экране входа — предустановленных учётных данных в публичном виде нет.


## Известные ограничения

Осознанно не реализовано в текущей версии (честно, а не забыто):
- Разграничение прав по ролям (RBAC) — поле роли в БД есть, проверки прав по нему нет
- CSRF-защита
- Загрузка файлов сканов паспорта на сервер (сейчас — только путь к локальному файлу)
- Автоматические тесты

Подробный технический разбор архитектуры, схемы БД и API — в папке [`docs/`](./docs).
