## Назначение

**HMS (Hotel Management System)** — веб-платформа для полного цикла управления гостиницей. Система позволяет управлять номерным фондом, гостями, бронированиями и предоставляет аналитику.

---

## Целевая аудитория

| Роль | Возраст | Описание |
|------|---------|----------|
| Менеджеры отелей | 25-45 лет | Управление бронированиями, аналитика, контроль |
| Администраторы ресепшена | 20-50 лет | Создание/отмена броней, работа с гостями |

## Роли пользователей

| Роль | Доступ | Статус |
|------|--------|--------|
| `admin` | Полный доступ ко всему | ⚠️ Аутентификация реализована, RBAC не используется (все пользователи имеют одинаковый доступ) |
| `user` | Стандартный доступ | ⚠️ Аутентификация реализована, RBAC не используется |
| **Анонимный** | Доступен только `login.html`. Защищённые страницы (`dashboard.html`, `rooms.html`, `guests.html`, `bookings.html`) требуют авторизации. При попытке доступа без логина происходит редирект или `401` от API. | ✅ JWT аутентификация реализована |

## Функциональность

### Реализовано ✅

| Модуль | Функции |
|--------|---------|
| **Номера** | CRUD номеров (с полями note, needs_cleaning, last_cleaned_at), фильтрация по типу/статусу (свободен, занят, недоступен), поиск, автоматический расчёт цены по типу, управление статусом "недоступен" с пометкой причины |
| **Гости** | CRUD гостей, поиск по имени/телефону/паспорту/email, серверная валидация (ФИО, email, паспорт), маски ввода (IMask.js) |
| **Бронирования** | Создание/отмена, фильтрация по статусу/датам, поиск, расчёт стоимости, уведомления о выездах, проверка пересечения дат, быстрый поиск гостя с инлайн-созданием |
| **Дашборд** | Статистика (активные брони, заезды, выезды), занятость номеров, графики (Chart.js), быстрые брони прямо с главной, последние бронирования, быстрое создание бронирования |
| **Лендинг** | Презентация системы, типы номеров, статистика, CTA |
| **Авторизация** | ✅ JWT аутентификация с httpOnly cookie, bcrypt хеширование паролей, session management |
| **Тёмная тема** | Переключение через localStorage |
| **Адаптивность** | Desktop (≥1024px), планшет (768–1024px), мобильный (≤768px) |

### Не реализовано ⬜

- **Авторизация (RBAC)** — нет проверки ролей
- **Календарь** бронирований
- **Отчёты** и аналитика (дополнительно к дашборду)
- **Revenue** — финансовые метрики
- **AI Assistant**
- **Уведомления** (email/SMS)
- **Загрузка файлов** (сканы паспорта)
- **Employee management**
- **Мульти-отель**

## Ограничения

| Ограничение | Описание |
|-------------|----------|
| Только один отель | Нет multi-tenant |
| Нет offline-режима | Требуется интернет |
| Только один тип бронирования | Нет групповых бронирований |
| Формат дат — строки на клиенте | На клиенте `ДД.ММ.ГГГГ`, в базе PostgreSQL DATE |
| Нет истории изменений | Нет audit trail |
| Нет бэкапа/восстановления | Требуется ручное управление |

## Сценарии использования

### Сценарий 1: Создание бронирования

1. Администратор открывает `bookings.html`
2. Нажимает "Создать бронь"
3. Выбирает гостя из списка
4. Выбирает свободный номер
5. Указывает даты заезда/выезда
6. Система рассчитывает стоимость
7. Нажимает "Создать бронь"
8. Номер автоматически помечается "занят"
9. Появляется toast-уведомление

### Сценарий 2: Просмотр дашборда

1. Администратор открывает `dashboard.html`
2. Видит статистику: активные брони, заезды, выезды
3. Видит занятость номеров (прогресс-бар)
4. Видит графики бронирований и типов номеров
5. Видит последние бронирования в таблице
6. Может предупредить о гостях с выездом сегодня

### Сценарий 3: Отмена бронирования

1. Администратор открывает `bookings.html`
2. Находит нужную бронь
3. Нажимает "Отменить"
4. Подтверждает в модалке
5. Бронь помечается "отменена"
6. Номер автоматически помечается "свободен"

### Сценарий 4: Управление номерами

1. Администратор открывает `rooms.html`
2. Видит все номера в виде карточек
3. Может фильтровать по типу/статусу и искать
4. Добавляет/редактирует/удаляет номера
5. Цена автоматически подставляется при выборе типа
