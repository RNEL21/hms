## ⚠️ Требование авторизации

Все эндпоинты, кроме `/api/auth/login`, `/api/auth/register` и `/api/auth/logout` (`server/middleware/auth.js`):

- Требуют валидный JWT токен в httpOnly cookie `token`.
- Ответ при отсутствии/невалидном токене: `401 { "error": "Не авторизован" }` или `401 { "error": "Сессия истекла, войдите заново" }`.

## Auth

### POST /api/auth/login

**Назначение:** Авторизация пользователя.

**Request Body:**
```json
{
  "login": "admin",
  "password": "123456"
}
```

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| login | string | Да | Имя пользователя |
| password | string | Да | Пароль (в открытом виде) |

**Response (200):**
```json
{
  "ok": true,
  "user": {
    "id": 1,
    "login": "admin",
    "role": "admin"
  }
}
```

**Response (400):**
```json
{ "error": "Введите логин и пароль" }
```

**Response (401):**
```json
{ "error": "Неверный логин или пароль" }
```

**Response (500):** — ошибка сервера.

**Авторизация:** После успешного входа сервер устанавливает httpOnly cookie с JWT токеном (7 дней). Cookie отправляется автоматически браузером при `credentials: 'include'`.

**Используется на страницах:** `login.html` (функция `doLogin()`), после входа — редирект на `dashboard.html`.

---

### POST /api/auth/register

**Назначение:** Регистрация нового пользователя.

**Request Body:**
```json
{
  "login": "user1",
  "password": "mypassword",
  "name": "Иван Иванов"
}
```

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| login | string | Да | Имя пользователя |
| password | string | Да | Пароль (мин. 6 символов) |
| name | string | Нет | Отображаемое имя |

**Response (201):**
```json
{
  "ok": true,
  "user": { "id": 2, "login": "user1", "role": "user" }
}
```

**Возможные ошибки:**

| Код | Ошибка | Причина |
|-----|--------|---------|
| 400 | `Заполните все поля` | Отсутствует login или password |
| 400 | `Пароль минимум 6 символов` | password.length < 6 |
| 409 | `Логин уже занят` | Duplicate entry (UNIQUE на login) |
| 500 | Ошибка сервера | |

**Используется на страницах:** `login.html` (функция `doRegister()`).

---

### POST /api/auth/logout

**Назначение:** Завершить сессию (logout).

**Request Body:** — отсутствует (тело запроса не требуется).

**Response (200):**
```json
{ "ok": true }
```

**Описание:** Очищает httpOnly cookie с токеном JWT. После этого запросы к защищённым эндпоинтам будут возвращать `401`.

**Используется на страницах:** Есть отдельная кнопка "Выйти" в интерфейсе (все страницы с sidebar).

## Rooms

### GET /api/rooms

**Назначение:** Получить список всех номеров (с фильтрацией).

**Query Parameters:**
| Параметр | Тип | Описание |
|----------|-----|----------|
| type | string (optional) | Фильтр по типу: "Одноместный", "Двухместный", "Полулюкс", "Люкс" |
| status | string (optional) | Фильтр по статусу: "свободен", "занят", "недоступен" |
| needs_cleaning | boolean (optional) | Фильтр по флагу уборки |

**Response (200):**
```json
[
  {
    "id": 1,
    "number": "101",
    "type": "Одноместный",
    "price": 3000,
    "status": "свободен"
  }
]
```

**Используется на страницах:** `dashboard.html`, `rooms.html`, `bookings.html`

---

### GET /api/rooms/:id

**Назначение:** Получить один номер по ID.

**Response (200):** — объект room
**Response (404):** `{ "error": "Не найдено" }`

**Используется на страницах:** нигде напрямую (фронтенд фильтрует массив на клиенте).

---

### POST /api/rooms

**Назначение:** Создать новый номер.

**Request Body:**
```json
{
  "number": "302",
  "type": "Люкс",
  "price": 7500,
  "status": "свободен",
  "note": "Комментарий (опционально)"
}
```

| Поле | Тип | Обязательное | Default | Описание |
|------|-----|-------------|---------|----------|
| number | string | Да | | Номер комнаты |
| type | string | Да | | Тип: "Одноместный", "Двухместный", "Полулюкс", "Люкс" |
| price | number | Да | | Цена за ночь |
| status | string | Нет | "свободен" | Статус: "свободен", "занят", "недоступен" |
| note | string | Нет | null | Примечание (например, причина недоступности) |

**Response (201):** — созданный объект room с id.

**Возможные ошибки:**

| Код | Ошибка | Причина |
|-----|--------|---------|
| 400 | `Номер, тип и цена обязательны` | Отсутствуют поля |
| 409 | `Такой номер уже существует` | Duplicate entry (UNIQUE на number) |

**Используется на страницах:** `rooms.html`

---

### PUT /api/rooms/:id

**Назначение:** Обновить номер.

**Request Body:** — все поля номера (number, type, price, status, note).

**Response (200):** — обновлённый объект room.

**Возможные ошибки:** 409 — дубликат номера.

**Используется на страницах:** `rooms.html`

---

### PATCH /api/rooms/:id/cleaning

**Назначение:** Управление флагом уборки номера.

**Request Body:**
```json
{ "needs_cleaning": true }
```

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| needs_cleaning | boolean | Да | `true` — помечать как требует уборки, `false` — снять пометку и установить `last_cleaned_at = NOW()` |

**Response (200):** — обновлённый объект room.

**Используется на страницах:** `rooms.html` (кнопка "Отметить убранным" на карточке номера)

---

### DELETE /api/rooms/:id

**Назначение:** Удалить номер.

**Response (200):** `{ "ok": true }`

**Используется на страницах:** `rooms.html`

**✅ Реализовано:** Проверка на активные бронирования. Если номер забронирован, возвращается `400` с сообщением об ошибке.

### POST /api/bookings

**Назначение:** Создать бронирование (транзакция).

**Request Body:**
```json
{
  "guest_id": 1,
  "room_id": 3,
  "check_in": "15.07.2025",
  "check_out": "20.07.2025"
}
```

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| guest_id | number | Нет* | ID гостя (или new_guest) |
| new_guest | object | Нет* | Новый гость (если guest_id не указан) |
| room_id | number | Да | ID номера |
| check_in | string | Да | Дата заезда (ДД.ММ.ГГГГ) |
| check_out | string | Да | Дата выезда (ДД.ММ.ГГГГ) |

*Должен быть указан либо guest_id, либо new_guest

**Бизнес-логика (транзакция):**
1. `BEGIN`
2. `SELECT ... FOR UPDATE` — блокировка номера
3. Проверка: номер существует?
4. Проверка: номер не занят?
5. Проверка: дата выезда > дата заезда
6. Проверка: отсутствуют пересечения с активными бронями
7. `INSERT INTO bookings` (при new_guest — сначала INSERT гостя)
8. `UPDATE rooms SET status='занят'`
9. `COMMIT`
10. Возврат полной записи с JOIN

**Response (201):** — созданная бронь с данными гостя и номера.

**Возможные ошибки:**

| Код | Ошибка | Причина |
|-----|--------|---------|
| 400 | `Все поля обязательны` | Отсутствуют поля |
| 400 | `Дата выезда должна быть позже даты заезда` | Неверная последовательность дат |
| 400 | `Неверный формат даты` | Формат не DD.MM.YYYY |
| 404 | `Номер не найден` | Неверный room_id |
| 409 | `Номер уже занят на выбранные даты` | Пересечение с активной бронью |
| 409 | `Гость с таким паспортом уже зарегистрирован` | При создании нового гостя |

**Используется на страницах:** `bookings.html`, `dashboard.html`

---

### PUT /api/bookings/:id/cancel

**Назначение:** Отменить бронирование (транзакция).

**Request:** — без тела.

**Бизнес-логика (транзакция):**
1. `BEGIN`
2. Проверка: бронь существует?
3. Проверка: бронь активна?
4. `UPDATE bookings SET status='отменена'`
5. `UPDATE rooms SET status='свободен' WHERE id=room_id`
6. `COMMIT`

**Response (200):** `{ "ok": true }`

**Возможные ошибки:**

| Код | Ошибка | Причина |
|-----|--------|---------|
| 404 | `Бронь не найдена` | Неверный id |
| 409 | `Бронь уже отменена` | Статус != 'активна' |

**Используется на страницах:** `bookings.html`

## Статус: ⚠️ — Проблемные эндпоинты

- **POST /api/auth/login** и **POST /api/auth/register** — эндпоинты работают, но UI `login.html` не использует их (mock-валидация)
- **Нет эндпоинта для logout** — нет сессий или JWT
- **Нет GET /api/bookings/stats на frontend** — dashboard вызывает `DB.getStats()`, который при подключённом API вызывает `/api/bookings/stats`, но `api.js` имеет дублирующий объект `DB`: первый — API-обёртка, второй — localStorage-mock (mock.js). Актуальный `api.js` экспортирует первый вариант.
