# Hotel Management System — Design System

*Версия: 1.0.1*  
*Последнее обновление: 2026-06-29*

---

## Product Vision

**HMS** — это современная платформа для полного цикла управления гостиницей, созданная для повышения эффективности и удовлетворённости клиентов.

### Чувство, которое создаёт интерфейс
**Тёплая премиальность с заботой о деталях.** Интерфейс должен вызывать успокоение и доверие, а не утомлять. Цвета и типографика создают атмосферу уюта, как в самом гостеприимном отеле.

### Тип софта
Веб-платформа для **полного цикла управления гостиницей** — персонала, работающего с Rooms, Guests, Bookings, Analytics, AI Assistant, Reports и Revenue.

### Целевая аудитория
- **Менеджеры отелей** (25-45 лет)
- **Администраторы ресепшена**
- **Владельцы малых гостиниц**
- **Персонал** (повара, уборщики, охранники)

Пользователи ценят скорость, надёжность и минималистичность. Они работают с 9 утра до поздней ночи и ценят ясность на фоне шума.

### Личность продукта
**Дружелюбный помощник, а не холодный сервис.** HMS говорит на одном языке с персоналом — понятно, по делу, без лишней терминологии.

### Бренд-значения
- **Гостеприимство** — забота о каждой детали
- **Чёткость** — ясные данные и понятные действия
- **Надёжность** — система работает, когда нужно
- **Элегантность** — красота в простоте
- **Всеядность** — интуитивный AI-помощник для персонала

## Design Philosophy

| Принцип | Объяснение |
|---------|------------|
| **Premium** | Чёткие линии, белое пространство, продуманные тени |
| **Warm** | Тёплая цветовая гамма, мягкие переходы |
| **Modern** | Современная типографика, скругления, стеклянные панели |
| **Functional** | Каждый элемент выполняет функцию |
| **Minimal** | Ничего лишнего. Только необходимое |
| **Spacious** | Дышащий интерфейс с достаточными отступами |

> Эти принципы существуют потому, что персонал гостиницы работает много часов. Утомлённый интерфейс убивает продуктивность.

## Future Features — Design Guidelines

Все новые страницы должны соответствовать следующим принципам:

### AI Assistant
- Стиль чата: сообщения в стиле "пузырьков"
- Аватарка помощника: тёплый оранжевый фон с белой иконкой
- Поле ввода: как в формах HMS

### Analytics / Reports
- Графики — в карточках с белым фоном
- Легенда — под графиком, горизонтально
- Экспорт кнопка справа в заголовке

### Notifications
- Выпадающий список под иконкой
- Маркер новых уведомлений — красная точка

### Calendar
- Месячный вид с цветовыми полосами занятости
- День — карточкой с бронями

### Revenue
- Статистика в виде карточек-чисел
- График дохода — линейный

### Settings
- Два столбца: профиль и настройки
- Кнопка "Сохранить" в правом верхнем углу

## Things To Avoid

❌ **Никогда не использовать:**

- Любой из дефолтных стилей Bootstrap
- Компоненты Tailwind без кастомизации
- Material Design элементы (боковые панели,FAB)
- Неоновые цвета
- Холодные синие диagrams
- Плотные, сжатые макеты
- Шрифт меньше 14px
- Большие градиенты
- Тяжёлые тени (более 20px)

## Rules for AI

При генерации нового UI следуйте этим правилам:

1. **Использовать только имеющиеся переменные CSS** (`--accent`, `--surface`, `--text-2` и т.д.)
2. **Соблюдать отступы:** `12px`, `16px`, `20px`, `24px`, `28px` — только из этого дизайна
3. **Не выдумывать новые цвета** — только из палитры
4. **Шрифты:** только `Golos Text`, `Outfit` и `Geist Mono` (.mono)
5. **Радиус:** `8px`, `12px`, `18px` — только из системы
6. **Компоненты:** переиспользовать существующие (`.card`, `.btn`, `.glass`)
7. **Анимации:** максимум `0.2s`, только если есть предыдущий пример
8. **Новые страницы** должны выглядеть так, будто были созданы в течение тех же дней, что и другие
9. **Проверять адаптацию под мобильные устройства**

## Protected Files

Никогда не модифицировать без явного разрешения:

- `.env` — учётные данные БД
- `package.json` — зависимости
- конфигурация подключения к базе данных

AI может изменить эти файлы только после подтверждения пользователя.

Также любое изменение JavaScript должно сначала начинаться с анализа существующего файла. Запрещено полностью переписывать файл без объективной необходимости. Новая логика должна встраиваться в существующую архитектуру и переиспользовать уже имеющиеся функции.

> HMS — это система для людей, которые работают сRooms. Дизайн должен облегчать, а не мешать.

## Component Hierarchy

### Base Components

Фундаментальные элементы, из которых состоят все страницы:

- **Button** — кнопки всех типов
- **Input** — текстовые поля форм
- **Select** — выпадающие списки
- **Badge** — статусные маркеры
- **Card** — контейнер для контента
- **Modal** — всплывающие окна
- **Toast** — уведомления

### Composite Components

Группы базовых компонентов для конкретных задач:

- **StatCard** — статистика с числом и label
- **RoomCard** — карточка номера
- **BookingCard** — карточка бронирования
- **GuestCard** — карточка гостя
- **SearchBar** — поисковая панель
- **FilterBar** — фильтры для списков
- **ChartCard** — графики и визуализации
- **Navigation** — боковое меню, хедер

### Pages

Полные страницы, использующие иерархию компонентов:

- **Dashboard** — главная панель
- **Rooms** — управление номерами
- **Guests** — база гостей
- **Bookings** — бронирования
- **Analytics** — аналитика
- **AI Assistant** — чат-помощник
- **Calendar** — календарь бронирований
- **Reports** — отчёты
- **Revenue** — финансы
- **Employees** — персонал
- **Settings** — настройки

**Принцип:** Компоненты переиспользуются. Никогда не создаются новые визуальные паттерны без необходимости.

## Room Card Specification

### Визуальная иерархия

1. **Статус** — бейдж в правом верхнем углу
2. **Номер комнаты** — крупнее всех, жирный шрифт Outfit
3. **Тип номера** — вторичный текст под номером
4. **Гость** — имя или "Свободен"
5. **Цена** — выделена цветом accent
6. **Действия** — кнопки внизу, минимальные

### Дизайн-правила

- **Без цветной полоски** сверху
- **Статус** отображается только бейджем
- **Номер** — самый сильный визуальный элемент
- **Действия** не должны доминировать
- **Пространство** — достаточные отступы
- **Эмоция** — премиальность отеля
- **Минимализм** — мало декорации

### Состояния

| Состояние | Внешний вид |
|-----------|-------------|
| **Hover** | Лёгкое увеличение, тень |
| **Active** | Сдвиг вниз на 1px |
| **Selected** | Рамка `accent`, фон `accent-dim` |
| **Disabled** | Прозрачность 50% |

## Consistency Rules

Каждая новая страница должна:

- Переиспользовать отступы из системы (`12px`, `16px`, `20px`, `24px`, `28px`)
- Применять ту же типографику (`Golos Text`, `Outfit`)
- Использовать существующие цвета палитры
- Соблюдать радиусы (`8px`, `12px`, `18px`)
- Воспроизводить те же тени и анимации
- Следовать компонентным паттернам

Новые страницы должны выглядеть, как будто были спроектированы в течение тех же дней, что и оригинальные.
